| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F   | Функциональные (Functionality)     |              |
| F1  | Пользователь видит на сайте список доступных депозитов с актуальными общими ставками | Для новых клиентов |
| F2  | Пользователь подает заявку на депозит через сайт, оставив свой номер телефона и Ф.И.О. | Для новых клиентов |
| F3  | Менеджер кол-центра видит заявки на депозиты в своей системе кол-центра и предлагает по ним особые условия | Для этого заявка с сайта должна передаваться в систему кол-центра, а также должна отображаться вся информация, неоходимая для предложения спец условий |
| F4  | Идентификация нового клиента обязательна и проводится в отделении банка | Новый депозит открывается только идентифицированному клиенту (проверка) |
| F5  | Пользователь видит в интернет-банке список доступных депозитов с актуальными общими и персонализированными ставками | Для существующих клиентов. Требуется реализовать персонализацию ставок через интеграцию интернет-банка с АБС или новым сервисом-калькулятором ставок по депозитам |
| F6  | Пользователь подает заявку на депозит через интернет-банк, указав счёт и сумму депозита | Для существующих клиентов |
| F7  | Пользователь подтверждает заявку на депозит через интернет-банк с помощью СМС-кода | Для существующих клиентов. Нужно реализовать соответствующую функциональность через новую интеграцию с СМС-шлюзом |
| F8  | Менеджер бэк-офиса по депозитам обрабатывает заявки на депозиты и подтверждает их условия в АБС | На этапе MVP. Потом автоматизировать проверки. Для этого заявки должны выгружаться из систем кол-центра в АБС |
| F9  | Пользователь получает СМС-уведомление после открытия депозита по заявке | Для всех клиентов. Через существующую интеграцию с СМС-шлюзом |
| F10  | Расчет и хранение ставок (общих и персонализированных) происходит в АБС или в отдельном сервисе-калькуляторе без ручного ввода и участия менеджеров бэк-офиса по депозитам и кредитам | Желательно в отдельном сервисе, т.к. расчет персонализированных ставок может давать ощутимую нагрузку в даты Х (изменение ключевой ставки, маркетинговые акции и т.д.) |
| F11  | Менеджеры бэк-офиса в АБС видят, подтверждают (общие) и при необходимости редактируют ставки по депозитам (общие и персонализированные) | Требуется на случай в исключительных ситуациях, когда требуется "зарезать" улучшенное предложение (нелояльный клиент или мошенник), или наоборот сделать предложение лучше ("супервип"). Обязателен аудит изменений |
| U   | Удобство использования (Usability) |              |
| U1  | Интерфейс работы должен быть максимально удобным для клиента | Потребуются привлечение экспертов UI/UX-дизайна, анализ аналогичных решений на рынке, а также проведение A/B-тестов с отслеживанием поведения пользователей и учетом конверсии в целевые действия |
| U2  | Интерфейс должен соответствовать корпоративному дизайну | Привычные для пользователей брендированные цвета и элементы |
| R   | Надёжность (Reliability)           |              |
| R1  | Все сервисы работают 24/7  | Минимизация недоступности услуг требуется в т.ч. во время работ. Обуславливает реализацию отказоустойчивости и использование резервного ЦОДа у интернет-банка в т.ч. для новых сервисов |
| R2  | Доступность сервисов 99.9% | Обуславливает необходимость горизонтального масштабирования. Для интернет-банка требуются доработки.
| P   | Производительность (Performance)   |              |
| P1  | Время отклика < 1 сек для всех операций | Нужно исправить долгую загрузку справочников при проведении платежей |
| P2  | Все системы, задействованные в онлайн-заявках, должны быть готовы к росту нагрузки | Обуславливает необходимость горизонтального масштабирования и настроенного мониторинга ресурсов (д.б. запас), а также проведения нагрузочных тестов для выявления узких мест |
| P3  | Часто используемые данные (условия тарифов, доступные продукты, ставки) кэшируются | Снижение нагрузки на сервисы сайта и интернет-банка, а также снижение требований к ресурсам серверов |
| P4  | Внедрен регулярный аудит запросов в БД АБС и оптимизация запросов в ТОПе по нагрузке | Уменьшение и контроль нагрузки на перегруженной БД АБС |
| S   | Поддерживаемость (Supportability)  |              |
| S1  | Необходимо предусмотреть разработку документации для дальнейшего расширения системы | Документирование всех задействованных систем (интернет-банк, сайт, АБС, кол-центр), API, потоки данных, архитектура, инфраструктурная карта |
| S2  | Минимизировать доработки функционала работы с СМС в ядре системы Интернет-Банка| Реализация требуемого бизнес-функционала для отправки СМС-кода силами команды разработки банка  (в т.ч. в виде отдельного сервиса) повысит экспертизу команды и улучшит сопровождаемость без привлечения подрядчика. В целом можно отнести и к ограничениям, но с т.зр. того, что этот модуль по развитию и поддержке на подрядчике, выбрал поддерживаемость |
| S3  | Проведение нагрузочного тестирования | С учетом критичности достаточной производительности систем, участвующих в открытии депозитов, нагрузочное тестирование должно быть интегрировано в процесс разработки, начиная с ранних этапов, что позволит выявить узкие места в архитектуре системы и предотвратить дорогостоящие исправления в будущем |
| +R  | + Ограничения (Restrictions)       |              |
| +R1 | Шифрование передаваемых через сайт данных клиентов (TLS/HTTPS) | Ф.И.О. + телефон, оставляемые на сайте при оформлении заявки на депозит - это перс. данные, ктоторые необходимо защищать |
| +R2 | Шифрование передаваемых через интернет-банк данных (TLS/HTTPS)  | При работе в интернет-банке могут передавать перс. данные и данные существующих клиентов, составляющие банковскую тайну, которые необходимо защищать |
| +R3 | Следует избегать прямой работы интернет-банка с API АБС в новых процессах, а также создания новых бизнес-процессов в АБС | Уже сейчас АБС перегружена. Без её редизайна и решения проблем с производительностью не стоит усугублять ситуацию, чтобы не остановить другие бизнес-процессы, критичные для деятельности банка |
| +R4 | АБС может масштабироваться только вертикально из-за используемой БД | Нужно избегать доп. нагрузки на БД АБС + учитывать, что она работает только в одном ДЦ |
| +R5 | В качестве очереди сообщений в приоритете рассмотреть использование Kafka  | На перспективу. Сейчас интернет-банк с ней не совместим - потребуются доработки |
| +R6 | При доработках следует в первую очередь использовать технологии и платформы, которые уже используются, или по которым в банке уже имеется экспертиза | СУБД: Oracle, MS SQL. Код: Delphi, PHP, React.js, Java, .Net, SQL. Повысить сопровождаемость |
| +R7  | Перевод интернет-банка на микросервисную архитектуру | Рассмотреть возможность в рамках MVP по открытию депозитов. Упростит дальнейшее развитие и масштабирование |
